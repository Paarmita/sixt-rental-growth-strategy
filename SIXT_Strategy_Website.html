Section 2 — Problem Framing

The Audit: Where Revenue Leaks

The gap between branch and digital RPR is not a product quality gap — it's an information asymmetry gap. The digital funnel today does little of what a branch agent does across moments, message framing, and customer-read — areas where current capabilities are largely static and uniform.

Section 3 — Strategic Framework

Three Levers. One Engine.

The strategy is built on a simple insight: branch agents outperform digital because they have more moments, better messages, and a read of the customer. We replicate all three.

Why? Our analysis suggests Moments contributes ~35% of the replicable gap, Messages ~30%, and Match ~35% of long-run potential — but Match carries the longest build time, which is why we sequence Moments and Messages first.

⏰
Lever 1

Moments

Multiply upsell touchpoints across the entire post-booking timeline — T-25h email, T-1h MCI funnel, on-rent push, mid-rental extension, and post-rental re-engagement.

💬
Lever 2

Messages

Shift from listing specs to selling outcomes. "More Luggage Space" beats "VW Tiguan Allspace 7-seat." Per-day micro-pricing and social proof eliminate sticker shock.

🎯
Lever 3

Match

A real-time propensity engine scores each customer across three product categories and serves ranked recommendations — no two customers see the same screen.

What We Chose Not to Do

  • Dynamic real-time pricing — deferred because SIXT's current pricing architecture requires a separate workstream not scoped within this programme.
  • Loyalty points for upsell — evaluated and deferred to Year 2 as it requires CLV modelling not yet scoped into this engagement.
  • Full AI chat recommendation — considered too high-friction for the T-1h urgency window and poses compliance uncertainty in multiple markets.

The hardest call was sequencing the UI overhaul (SI-P1A) ahead of the personalisation engine (SI-P2A). The engine is higher long-run value — but it has a 6–8 week ML build dependency. Shipping the engine first would mean 6–8 weeks of zero revenue impact. The UI overhaul ships in days and proves the messaging hypotheses that the engine will later personalise at scale.

Section 5 — Experimentation Framework

10 Experiments. 3 Phases. One Scientific Approach.

Every personalisation hypothesis is a bet. The framework enforces single-variable testing, pre-registered MDEs, guardrail metrics, and a multi-touch attribution model to prevent contamination across the journey's touchpoints.

Experimentation principles governing all tests are documented in Appendix 2 — A/B Testing Principles.

Copy and UI changes only — no ML required. Deployable immediately at Tier 1 branches while the personalisation engine is being built in parallel. Proves the core messaging hypotheses before adding scoring complexity.

Six non-negotiable principles that govern every experiment in the portfolio. These prevent the common failure modes of underpowered tests, contamination, and learning-free failures.

#PrincipleWhy It Matters
1One variable per testChange only one element per variant to isolate causal inference. No multi-variable shortcuts.
2Pre-register MDEDefine minimum detectable effect and required sample size before launch. No post-hoc power calculation.
3Guardrail metricsEvery test defines guardrails — MCI completion rate, NPS, cancellation rate. A revenue win that breaks guardrails is a failure.
4Segment analysisAll results broken down by the four customer segments. A win for Business Travellers may be harmful for First-Timers.
5Attribution-cleanMulti-touch journeys use holdout groups. Users enrolled in EXP-005 (email) excluded from EXP-001 (price framing).
6Ship or LearnA failed test is a data point. Log all learnings. Never run the same test twice — always build on what was learned.

MDEMinimum Detectable Effect — the smallest true uplift an A/B test is powered to reliably detect at a given significance level (α) and statistical power (1−β); must be defined before launch.

Epsilon-Greedy ArmA Reinforcement Learning exploration–exploitation strategy: with probability ε the algorithm explores a random offer (exploration); with probability 1−ε it serves the highest-scoring offer known so far (exploitation). Balances learning with revenue optimisation.
